How It Works

The website collects answers through forms. Spring Boot passes them into Java interview classes — the same logic a Scanner console program would run after nextLine().

01

Choose a practice set

Enter your name, pick a category, and select 10, 25, 50, 75, or 100 questions.

02

Answer one question at a time

Type a technical explanation. Submit sends the text to the Java backend, not a JavaScript scorer.

03

See matched keywords

The matcher counts hits, awards marks, and explains missing concepts before the next question.

Implementation Highlights

Question class

Stores interview questions, expected keywords, categories, difficulty, and marks.

ArrayList

Stores and manages the collection of interview questions and keyword lists.

OOP

Question, Student, Interview, KeywordMatcher, AnswerEvaluator, ScoreManager, PerformanceAnalyzer, FeedbackGenerator.

Keyword matching

Lowercases the answer, strips punctuation, and counts expected concept matches.

Score calculation

Marks = (matched keywords / total keywords) × maximum marks.

Percentage & grading

Java computes total score, percentage, and Excellent → More Practice Required.

AI-style feedback

Personalized suggestions from weak categories. No fake neural-network claim — this is rule-based Java intelligence.

Scanner vs web input

Console labs use Scanner. This app uses web forms as the equivalent input channel. See ScannerInputDemo.

Input Used

1. Predefined questions

Loaded into Java at startup from QuestionRepository.

2. Expected keywords

Important concepts stored with every question object.

3. Student answers

Entered in the website textarea and POSTed to Spring Boot.

4. Student information

Name, category, and number of questions from the start form.

Output Produced

Student name, total questions, total score, percentage, performance grade, category-wise performance, keyword matching results, strong areas, weak areas, and AI-style suggestions.
